Receipts for
every preview.

katalepsis runs your Playwright tests, or checks written in plain English, against a preview deployment. You get a report you can paste into the pull request: what passed, what broke, what couldn't run, and what nobody tested.

Open source and local. Agent checks use your own key, and everything else needs none.

katalepsis run

Your Playwright tests

katalepsis verify

Checks without tests

Every check ends up passed, failed, blocked or not tested

Passed

Playwright said so, or an assertion in the browser did.

Failed

Something on the page was wrong. You get the assertion that caught it, plus the screenshot, video and trace.

Blocked

The preview was down or the browser wouldn't start. Not your app's fault, and not counted against it.

Not tested

Skipped or filtered out. Listed by name, so nobody assumes it passed.

Works with the Playwright tests you already have

Read the base URL from KATALEPSIS_BASE_URL and you're done. katalepsis uses your Playwright install and your config, asks the preview if it's up before starting a browser, and bundles whatever Playwright recorded.

  • No new test format, no AI key
  • --grep and --project work as usual
  • Every file in the bundle is listed with its SHA-256
  • A pass that needed a retry is marked flaky
  • Warns when your config ignores the preview URL
  • A preview built from another commit can't pass
~/your-app
$ katalepsis run --url http://127.0.0.1:4173 --cwd apps/demo-form

Agent checks only pass when the browser agrees

For the things nobody wrote a test for, describe what should happen. A model with your Anthropic, OpenAI or OpenRouter key clicks through it in a real browser. To pass, it has to cite an assertion katalepsis ran that shows something it changed. When one of the models we tested cited a heading that was already on the page, the check was blocked.

  • Keys stay in your keychain or environment
  • Caps on steps, tokens and time per check
  • The browser can't leave your preview's domain
  • Screenshots go in the report, never to the model
  • One action at a time, a fresh browser per check

Your coding agent can check its own work

katalepsis runs as an MCP server, so whatever agent harness you use can test a preview and read the report without you in the loop. Same rules: the agent gets results, not a browser it can talk its way through.

  • Three tools: run tests, run checks, read a report
  • Locked to one folder, one run at a time
  • Never takes a key as an argument
