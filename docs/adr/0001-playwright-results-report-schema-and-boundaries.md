# ADR 0001: Playwright results, report schema, credentials and browser boundaries

- Status: accepted for M0 and M1
- Date: 2026-10-10

## Context

katalepsis answers one question for a reviewer: what behaviour of this preview was checked, what passed, what failed, and what was not checked. The first version runs a project's existing Playwright tests. Later versions add agent-driven checks (M2), a local MCP server (M3) and a GitHub Action (M4).

## Decisions

### 1. Playwright results are authoritative

katalepsis never decides whether a Playwright test passed. It reads Playwright's JSON reporter output and maps it:

| Playwright outcome                                                                                                     | katalepsis status                                      |
| ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `expected`                                                                                                             | passed                                                 |
| `flaky`                                                                                                                | passed, marked flaky, with every attempt listed        |
| `unexpected`, last result `failed` or `timedOut`                                                                       | failed                                                 |
| `unexpected`, error is a network failure naming the preview origin, such as `net::ERR_CONNECTION_REFUSED at <preview>` | blocked, `preview-unavailable`                         |
| `unexpected`, the browser could not launch                                                                             | blocked, `browser`                                     |
| `unexpected`, last result `interrupted`                                                                                | blocked                                                |
| `skipped`                                                                                                              | not a check; listed under "Not tested" with the reason |

A failure to reach the preview, or a browser that cannot start, is blocked instead of failed because the test never reached the behaviour it checks. A network failure for any other host stays failed: an app calling a dead or wrong API host is a real regression. Summaries are rendered from validated data. No model writes or changes a status.

### 2. One versioned report schema

`packages/core/src/schema.ts` defines `VerificationRun`, `VerificationCheck`, `EvidenceFile`, `NotTested` and `RunError` with Effect Schema, at `schemaVersion: 1` (2 since [ADR 0004](0004-preview-commit-alignment.md)). The manifest is decoded against the schema before it is written, so an invalid manifest is a bug that stops the run with exit code 4, not a silently broken report.

Run status: failed if any check failed; otherwise blocked if any check is blocked, the run has a run-level error, or no check ran; otherwise passed.

A run with filtered or skipped tests can pass if at least one check ran and every check that ran passed. Tests excluded by `--grep` or `--project`, and tests skipped with `test.skip()` or `test.fixme()`, are listed under "Not tested" with the reason, and the headline shows the count. Filtering is an explicit choice by the person running the tool, and skips are a choice made in the test suite; in both cases the report makes the gap visible instead of turning it into a block. A run in which nothing ran is blocked.

This departs on purpose from the plan's wording that a run passes only if "all declared checks passed". Under that wording, any `--grep` run or any suite with one `test.skip()` could never pass, which would push people to stop filtering or to delete skips. A test that Playwright listed but never reported is different: it is not a choice, so it blocks the run with an `infrastructure` error. Listing runs with `KATALEPSIS_BASE_URL` set, so a config that reads it declares the same tests for listing and running.

Evidence paths are relative POSIX paths inside the bundle. File names are generated by katalepsis, never taken from test output, and every path is checked so it cannot leave the bundle. Each file has a byte length and SHA-256.

The commit is `git rev-parse HEAD` of the project checkout, or `null`. It is never guessed. The report says that katalepsis does not confirm the preview was built from that commit. [ADR 0004](0004-preview-commit-alignment.md) adds the commit the preview reports and compares the two.

### 3. Passing the preview URL to existing tests

Playwright has no command-line option for `baseURL`. katalepsis sets `KATALEPSIS_BASE_URL` for the test process, and the project's config reads it. `katalepsis init` checks for this and prints the snippet. The report states that katalepsis cannot confirm the config reads the variable.

The alternative, a generated wrapper config, was rejected for M1. Playwright resolves `testDir`, `outputDir`, setup files and web server paths relative to the config file, so a wrapper in another directory changes their meaning.

katalepsis does not override the project's screenshot, video or trace settings. When a failed check has no screenshot, video or trace, the report says so and names the config setting that would capture it.

Before running Playwright, katalepsis requests the preview URL. A network error or an HTTP 502, 503 or 504 response marks every selected test blocked without starting a browser.

### 4. Credentials (M2, not built yet)

Following [the reference review](../reference-review.md):

- Lookup order: environment variable, then OS keychain, then missing. CI uses the environment only.
- Keys are never stored in preferences, report bundles, logs or MCP results. MCP tools take provider and model names, never keys.
- Redaction happens before anything is written. M1 already redacts preview URL query values in messages, logs and the manifest.
- Running existing Playwright tests never needs an AI key.

M1 adds no credential dependency.

### 5. Browser and agent boundaries (M2 and M3, not built yet)

- Deterministic Playwright Test execution and agent-driven checks are separate paths that produce the same `VerificationCheck` shape. Agent checks will use `source: "agent"` and must cite evidence for a pass; no evidence means blocked.
- Agent browser control goes through a small browser interface backed by the Playwright library. Playwright MCP may be one adapter behind that interface. It is not the product's API.
- The katalepsis MCP server exposes high-level operations (run tests, check a page, get a report), not raw browser actions.

### 6. Effect services

I/O sits behind Effect services so the orchestrator can be tested with fakes: `PlaywrightRunner` (locate, list, run), `PreviewProbe` and `RunMetadata`. Evidence copying and report writing are plain Effect functions over the file system. On macOS and Linux, Playwright and its test workers run in a process group of their own. Browsers and ffmpeg run in separate groups that Playwright manages. On timeout, on Ctrl-C, SIGTERM or SIGHUP, or when the Effect is interrupted, katalepsis sends SIGTERM to Playwright's group, so Playwright closes its browsers. It escalates to SIGKILL after 5 seconds, waits for Playwright to exit, and kills anything left in the group; browsers and ffmpeg also exit when their pipes to Playwright close. A second Ctrl-C kills the group at once and exits. A cancelled run still writes a blocked report with one cancellation error, and no stage after the cancellation starts Playwright. A failed listing also stops the run before Playwright runs the tests. Process and reporter failures become run errors in the report, with the tail of Playwright's output and the full log in `evidence/run/`. Only bad input or a missing Playwright install stops before a bundle is written. On Windows, only the Playwright process itself is signalled; this is untested.

## Consequences

- Projects must make their Playwright config read `KATALEPSIS_BASE_URL`. This is one line, and `init` shows it.
- The JSON reporter replaces the project's configured reporters during a katalepsis run.
- Evidence files are copied as Playwright wrote them. Screenshots, videos and traces are not redacted, and the report says so.
